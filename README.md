# Sonora — локальная аудиостудия

Веб-приложение на React, TypeScript и Vite: загрузите трек, примените 10-полосный эквалайзер и дополнительные настройки, слушайте результат и скачайте полную обработанную копию в WAV. Аудиофайлы обрабатываются в браузере и не отправляются на сервер.

## Публикация на GitHub Pages

GitHub Actions workflow собирает и тестирует ветку `arena/566f0f92-audiowithequalizer` и `main`, затем публикует сборку на [https://flare-award.github.io/AudioWithEqualizer/](https://flare-award.github.io/AudioWithEqualizer/). Перед первой публикацией в настройках репозитория **Settings → Pages → Build and deployment → Source** нужно выбрать **GitHub Actions**. До этого шага GitHub Pages не активирован для репозитория. Сборка настроена на URL-путь проекта `/AudioWithEqualizer/`.

## Локальная разработка

Требуются Node.js 18+ и npm.

```bash
npm install
npm run dev
```

Vite напечатает локальный адрес. Для production-сборки и её предпросмотра:

```bash
npm run build
npm run preview
```

Запуск тестов:

```bash
npm test
```

## Возможности

- Загрузка выбором файла или перетаскиванием; файл воспроизводится локально через браузерный `<audio>` и Web Audio API.
- Плеер с временными метками, перемоткой, громкостью мониторинга, воспроизведением и паузой. Регулятор мониторинга находится после общей DSP-цепочки и не меняет экспорт; для прямого сравнения с WAV оставьте его на 100%.
- Десять полос: 60, 170, 310, 600 Гц; 1, 3, 6, 12, 14 и 16 кГц; отдельное предусиление. Все значения регулируются в пределах −20…+20 дБ.
- Обход всей цепочки обработки одним переключателем. В режиме обхода сигнал не проходит эквалайзер, предусиление, панорамирование и сведение в Mono.
- Mono, баланс L/R, встроенные пресеты Flat, Bass Boost, Treble Boost, Rock, Pop, Classical и Vocal. Изменение любого параметра переводит активный пресет в Custom.
- Пользовательские профили (все параметры, включая Mono и баланс) сохраняются в `localStorage`; одинаковое имя перезаписывается только после подтверждения, удаление также требует подтверждения. Числового лимита профилей нет — доступный объём ограничен самим хранилищем браузера.
- Офлайн-экспорт всего трека в WAV независимо от текущей позиции воспроизведения. Повторный запуск экспорта блокируется до завершения текущего.
- Предупреждение о потенциальном клиппинге. Экспорт не добавляет нормализацию или лимитер.

## Обработка и принятые допущения

Справочная страница расширения описывает 10 полос «как в VLC», предусиление и профили, но точные типы фильтров, добротность и внутреннюю реализацию его DSP не раскрывает. Поэтому Sonora не заявляет идентичность звучания: здесь каждая полоса сделана как peaking-фильтр Web Audio API с Q = 1.4, частоты — из требований, а предусиление преобразуется из dB в линейный gain. Параметры полос и топология соединений общие для графа прослушивания и `OfflineAudioContext` экспорта. Медиаэлемент удерживается на unity gain, а пользовательская громкость мониторинга применяется отдельным gain-узлом **после** DSP-цепочки: браузерные различия в обработке `HTMLMediaElement.volume` не меняют уровень сигнала до эквалайзера. Экспорт рендерится с unity monitor gain, без скрытой нормализации. Если мониторная громкость снижена, воспроизведение намеренно будет тише экспорта; для точного сравнения установите 100%. Алгоритмы кодирования и ресемплинга браузера могут давать небольшие отличия.

Выход экспорта — несжатый 16-битный PCM WAV в исходной частоте дискретизации; если исходный сигнал моно или включён Mono, офлайн-цепь может сформировать двухканальный WAV с одинаковыми каналами. MP3-кодирование не реализовано: расширение файла не используется для имитации MP3.

Поддерживаемые для загрузки форматы зависят от декодеров конкретного браузера и ОС. Обычно браузер умеет воспроизводить MP3 и WAV; поддержка Ogg/Opus, AAC/M4A, FLAC, AIFF и других кодеков различается. Приложение передаёт файл браузерному декодеру, показывает ошибку, если тот не может декодировать аудио, и не перекодирует вход при воспроизведении.

Большие файлы могут занимать много памяти при декодировании и офлайн-рендере. Экспорт файлов больше 150 МБ отклоняется заранее; также действует ограничение расчётной рабочей памяти около 700 МБ после декодирования. Реальный расход зависит от браузера, числа каналов и реализации `OfflineAudioContext`; браузер может ограничивать его и раньше. Прогресс экспорта показывает этапы, но Web Audio API не предоставляет универсальный точный процент OfflineAudioContext-рендера.

Это сайт для локальных загруженных файлов, а не браузерное расширение: он не управляет аудио других вкладок или приложений. Воспроизведение и Web Audio API используют ресурсы устройства; выключение цепочки обработки не означает нулевую загрузку CPU всего плеера.
